## 7. Captura Real — `microfone → PCM → Vosk = EMPTY`

### 7.1 Dados Confirmados (produção regenerada, sem logs ChatAssistant)

- Microfone abre: **PASS** (realme 48k mono)
- `AudioContext` sampleRate 48k, mono, preparação/resampling 16k OK
- Vosk load OK, WAV→Vosk PASS (122 chars)
- Mic→PCM→Vosk **EMPTY** (não PARCIAL 1 palavra, mas vazio) — difere do sintoma VOZ-006/007 `1 palavra`, mas mesma família (PCM sem fala útil)

### 7.2 Hipóteses End-to-End (sem alterar código, apenas análise)

**a) Captura sem sinal (RMS≈0) — mais provável para EMPTY:**

- `ScriptProcessorNode` requer `AudioContext` em estado `running`. Se `AudioContext.state === 'suspended'` após `captureAudio`, `onaudioprocess` nunca dispara → `chunks` vazio → `pcm.length===0` → `LIFECYCLE_EMPTY` → "Nenhuma fala detectada".
- `captureAudio` cria `AudioContext({sampleRate: ctxRate})` [`capture.ts:83`] mas **não chama `audioContext.resume()`** nem verifica `state`. Em lab, `AudioContext` criado sem `resume` também, mas em desktop Chrome após gesture (`getUserMedia` é gesture) o contexto frequentemente já está `running` — em Android Chrome 152 pode permanecer `suspended` até `resume()` explícito, especialmente com policy de autoplay.
- **Evidência indireta:** `voiceController.ts:207` cria `recorderFactory` com `stream` e `audioContext` já existente, mas `recorder.start()` [`capture.ts:163`] só faz `source.connect(processor); processor.connect(destination)` — não `audioContext.resume()`. Se `state` for `suspended`, `onaudioprocess` silencia.
- **Por que WAV passa:** WAV usa `decodeAudioData` offline, não `getUserMedia` nem `AudioContext` de captura — não depende de `resume`.

**b) Perda do último bloco (VOZ-007 H1):**

- Explicaria `1 palavra` (truncamento 85ms) mas não `EMPTY` (4.9s → 4.8s ainda teria fala). Para `EMPTY`, precisaria perda total (ex: `chunks` nunca preenchido), não parcial.
- Ordem `recorder.stop()` (concat) → `capture.cleanup()` (close) já analisada VOZ-007 §8: `close()` não destrói PCM já copiado, mas `finished=true` antes de `onaudioprocess` pendente descarta. Para `EMPTY`, `chunks` estaria vazio antes do `stop()`.

**c) Ordem `start/stop`:**

- `start()` seta `recordingStartMs = Date.now()` **depois** de `createPcmRecorder` mas **antes** de `recorder.start()` — correto. `stop()` lê `recordingWallTimeMs = Date.now() - recordingStartMs` — correto. Não há corrida `stop()` fechando stream antes de copiar último bloco além de `finished` flag (§7 Fase 7).

**d) Resampling:**

- `resampleTo16k` linear 48k→16k ratio 3.0 — se `pcm` vazio (`0` samples), `resample` bypassa e `pcm16k` também 0 → Vosk recebe 0 samples → `VOSK_INPUT` `samples 0` → `VOSK_RESULT` empty. Resampling não é causa primária de EMPTY, mas preserva vazio.

**e) PCM enviado ao Vosk é mesmo da captura:**

- **Sim** — `voiceController.stop():225 pcm = recorder.stop()` → `237 pcm16k = resampleTo16k(pcm)` → `251 engine.transcribe(pcm16k,16000)` → `vosk.ts:88 transcribeWithVosk(pcm, sampleRate)`. Não há cópia divergente. Lab usa mesma `transcribeWithVosk`, mas PCM de origem diferente (fixture vs mic).

**f) ChatAssistant usando implementação diferente do laboratório:**

- **Sim** — lab usa `page.tsx:157` `createPcmRecorder` inline com `capturing` flag local + `setTimeout 1000`; ChatAssistant usa `VoiceInputController` com `gen` token + `recordingStartMs` + `captureAudio` (VOZ-006). Não são igualdades — instrumentação deve distinguir.

## 8. Causa da Ausência dos Logs

### Classificação

| Causa | Evidenciado | Descartado |
|---|---|---|
| `FLAG_NOT_IN_BUNDLE` | Não — bundle `954` tem `a(){return!0}` (flag true) | **Eliminada** |
| `INSTRUMENTED_MODULE_NOT_USED` | Não — `6700` contém `CAPTURE_START/STOP` | **Eliminada** |
| `CHATASSISTANT_BYPASSES_CONTROLLER` | Não — único import `useVoiceInput` → `VoiceInputController` | **Eliminada** |
| `CONSOLE_FILTERING` | **Provável** — `voiceDebugLog` usa `console.debug` que em Chrome DevTools é **oculto** a menos que nível `Verbose` esteja ativo (padrão é `Info`). Usuário com `Info` veria zero `[VOICE_DEBUG]`. `voiceDebugInfo` usa `console.info` (visível) mas nenhum log crítico usa `info`. | **Candidata principal** |
| `CODE_PATH_NOT_REACHED` | Parcial — `CAPTURE_START` só após `getUserMedia` + `engine.load` sucesso. Se `AudioContext` suspenso, `start()` completa mas `CAPTURE_STOP` mostraria 0 samples. Sem Verbose, não se sabe se `CAPTURE_START` chegou. | **Candidata secundária se filtering descartado** |
| `UNKNOWN` | — | — |

**Veredito ausência de logs:** `CONSOLE_FILTERING` **(console.debug → Verbose)** é a causa mais plausível e verificável sem alterar código: o bundle contém flag true e instrumentação, mas Chrome Android remote debugging filtra `debug` por padrão. Alternativa `CODE_PATH_NOT_REACHED` exigiria que `start()` falhasse silenciosamente (ex: `engine.load` pendente) — mas mic abre, então `start()` chegou a `recording`.

**Evidência bundle:** `954` tem `function a(){return!0}` (flag true) e `console.debug("[VOICE_DEBUG]"` em 9 chunks; `6700` tem todos eventos. Se `isVoiceDebugEnabled()` fosse false, minifier teria eliminado branches (`if(!0)` dead code), mas logs permanecem no bundle — prova que `isVoiceDebugEnabled` é `true` e branches preservados.
