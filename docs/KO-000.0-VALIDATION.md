## 2. Resumo das alterações

O caminho Base64/Filesystem (`modelManager.ensureAvailable() → download 92MB → Uint8Array → encodeBase64 123MB → Filesystem.writeFile → bridge 150 MB → OOM growth limit 402 MB`) foi **removido do fluxo efetivo em Android nativo**. O `KokoroBrowserRuntime` agora recebe `assetUrls` com `baseUrl = https://raw.githubusercontent.com/Joelgonn/vanzacarias/tts-assets-v1/` e o Worker faz `fetch` direto (1 cópia `Uint8Array` + WASM heap), sem `CapacitorStorage`. Web mantém mesmo Worker/WASM via `/tts/worker.js` + `/tts/wasm/*` estático (200). Modelo voltou ao APK via `prepare` (offline futuro, mas sprint usa GitHub raw para evitar OOM imediato).

## 4. Fluxo final do TTS

```
ChatAssistant.tsx:408 noteResponse→invalidate()+unlock() (FIX-001 gesto A/B)
  → chatTtsController noteResponse → buildSpeakable gate ≥4 palavras → speakPrepared → orchestrator.speak
  → TtsService.load() → isNativeForTts=true → skip modelManager.ensureAvailable() (AC-01)
  → KokoroBrowserRuntime.load() → worker.postMessage({kind:"init", assetUrls: GitHub raw, wasmPaths:"/tts/wasm/"})
  → Worker init: Promise.all(fetchBytes(model 92MB) + fetchText(tokenizer) + fetchBytes(voice 0.5MB)) → ort.InferenceSession.create(modelBytes, {wasm}) → post ready
  → synthesizer.enqueue → worker.postMessage({kind:"synth", text:"Olá! Esta é uma resposta de teste do assistente."})
  → vozzPhonemize + tokenize 115 + chunk ≤510 + ort.Tensor + session.run → waveform Float32 24kHz → concat 0.12s → encodeWav → post(synth-result, [audio.buffer,wav.buffer]) transfer
  → AudioResult {samples, sampleRate 24000, durationSec, wav}
  → orchestrator PLAYING → player.play(audio) → resolveUnlocked() fast-path running → createBuffer(1,len,24000)+copyToChannel → BufferSource → destination → onended → ENDED
```
