## 1. Problema (F01)

**Anomalia relatada:** em frases com pausa interna (~1 segundo), a transcrição perdia as palavras ANTES da pausa — só o trecho após a pausa aparecia.

**Cause raiz confirmada no worker vosk-browser:** o worker (`node_modules/vosk-browser/dist/vosk.js`, worker base64 → `vosk-worker.js`) emite **múltiplos eventos `result`** durante uma única sessão:

| Fonte no worker | Condição | Evento |
|---|---|---|
| `processAudioChunk` (AcceptWaveform) | Kaldi endpoint (pausa) atingido | `{event:"result"}` — 1 por endpoint (`vosk-worker.js:362-368`) |
| `processAudioChunk` (AcceptWaveform) | sem endpoint | `{event:"partialresult"}` — 1 por chunk |
| `retrieveFinalResult` (FinalResult) | chamada após último chunk | `{event:"result"}` — exatamente 1 (`vosk-worker.js:380-392`) |

**Bug no `transcribeWithVosk` (baseline):**

```
msg.result.text → finalText (SOBRESCREVE)
```

Cada evento `result` sobrescrevia o texto anterior. Numa frase com endpoint interno ("quero alterar minha dieta" [Endpoint] "porque estou sentindo muita fome"):

- evento `result` #1 (endpoint interno) → `finalText = "quero alterar minha dieta"`
- evento `result` #2 (retrieveFinalResult) → `finalText = "porque estou sentindo muita fome"` ← **sobrescreve o #1**

Resultado final: só o trecho **após** a pausa. Foi exatamente o que o auditor descreveu.

---

## 2. Abordagem Rejeitada (por quê o óbvio não funciona)

Uma primeira tentativa corrigiu a sobrescrita acumulando em `segments[]`, mas manteve a sinalização de término por `afterRetrieve` ("primeiro `result` após retrieveFinalResult → finish"). **Isso não funciona**: o worker e o main thread se comunicam por macrotasks (fila FIFO + `postMessage`), então os eventos chegam **depois** do bloco síncrono que lê `afterRetrieve=true` e chama `retrieveFinalResult()`. Ou seja, mesmo os `result` intermediários são recebidos quando `afterRetrieve` já é `true` → `finish()` disparava no 1º evento, e só o primeiro segmento sobrevivia.

Nenhum hack de `setTimeout`/`queueMicrotask` foi usado — seriam não-determinísticos (a especificação proíbe depender de timing).

---

## 3. Correção Implementada (`src/lib/voice/stt/vosk.ts` — cirúrgica)

**Contrato do worker (verificado no código):** exatamente **1 resposta** (result OU partialresult) por `acceptWaveformFloat` + **1 resposta** `result` do `retrieveFinalResult`. `createRecognizer` não emite resposta de recognizer (envia `undefined` — filtrado no `handleMessage`), e o `result` do `removeRecognizer` chega após o recognizer ser desmarcado do map (não é despachado). Logo, o número de respostas esperadas é determinístico:

```
expectedResponses = totalChunks + 1    // 1 por audioChunk + 1 do retrieveFinalResult
```

**Algoritmo final:**

```ts
const totalChunks = processedPcm.length > 0 ? Math.ceil(processedPcm.length / chunkSize) : 0; // chunkSize 4096
const expectedResponses = totalChunks + 1;
const segments: string[] = [];          // acúmulo de resultados finais em ordem

recognizer.on('result', (msg) => {
  const trimmed = msg?.result?.text?.trim();
  if (trimmed && trimmed !== segments[segments.length - 1]) segments.push(trimmed); // dedup (nunca duplica)
  responsesReceived++;
  if (responsesReceived >= expectedResponses) finish();                              // após o ÚLTIMO
});

recognizer.on('partialresult', () => {   // só conta; texto NUNCA entra nos segments
  responsesReceived++;
  if (responsesReceived >= expectedResponses) finish();
});
```

- `finish()` **só dispara quando todas as respostas chegaram** → o último evento é sempre o `result` do retrieveFinalResult.
- `partialresult` é contabilizado (para a contagem), mas o texto é **descartado** (Teste B).
- `joinSegments() = segments.filter(Boolean).join(' ')` → separação com **um único espaço**, bordas trimadas (Teste E).
- Guard de 30s preservado como rede de segurança (se o worker nunca responder, finaliza com o que acumulou).

**Caso especial:** PCM vazio → `totalChunks=0`, `expectedResponses=1` → só o retrieveFinalResult conta. Frases curtas (sem endpoint interno) → todos os chunks são partialresult + 1 retrieve → resultado idêntico ao baseline VOZ-008.8.
