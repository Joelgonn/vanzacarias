## 1. Implementação

**Arquivo alterado:** `src/lib/voice/stt/vosk.ts` — `transcribeWithVosk(pcm, sampleRate, model)`

**Alteração realizada (única):**

- **Antes (VOZ-008.7):**

  ```ts
  recognizer.acceptWaveformFloat(pcm, sampleRate);
  acceptEnd = Date.now();
  setTimeout(() => {
    afterRetrieve = true;
    retrieveStart = Date.now();
    voiceDebugLog('VOSK_RETRIEVE', ...);
    try { recognizer.retrieveFinalResult(); } catch {}
  }, 100);
  ```

  Envio único de todo o PCM (110592 samples) + espera fixa 100ms antes de `retrieveFinalResult()` — truncava áudio real de 6.9s no Android Chrome (Worker ainda processando quando `retrieve` chamado).

- **Depois (VOZ-008.8):**

  ```ts
  const chunkSize = 4096;
  for (let i = 0; i < pcm.length; i += chunkSize) {
    const chunk = pcm.subarray(i, Math.min(i + chunkSize, pcm.length));
    recognizer.acceptWaveformFloat(chunk, sampleRate);
  }
  acceptEnd = Date.now();
  afterRetrieve = true;
  retrieveStart = Date.now();
  voiceDebugLog('VOSK_RETRIEVE', { samples, sampleRate, acceptEnd, retrieveStart, acceptToRetrieveMs, chunks: Math.ceil(pcm.length / chunkSize) });
  try { recognizer.retrieveFinalResult(); } catch {}
  ```

  - PCM dividido em chunks de **máximo 4096 samples** (`subarray` sem cópia)
  - Todos os samples enviados (`for` cobre `0..length`)
  - Último chunk pode ser `<4096` via `Math.min`
  - `retrieveFinalResult()` ocorre **imediatamente após todos os chunks** (sem `setTimeout 100ms`)
  - `guard` de **30s** (`setTimeout finish 30000`) preservado
  - PCM vazio (`length 0`) → loop 0 iterações → `retrieve` direto → `empty` sem erro

**Validação estática:**

```
PCM
 ↓ chunks de 4096
 ↓ acceptWaveformFloat para cada chunk
 ↓ retrieveFinalResult (após loop)
```

- Não existe mais `acceptWaveformFloat(pcm)` único — verificado `grep` 0 ocorrências
- Não existe `setTimeout(..., 100)` para finalização — `grep` apenas `guard 30000` e `MODEL_LOAD_TIMEOUT 120000`
- Nenhum fallback para fixture introduzido (`micPcmRef`/`fixtureRef` intactos)
