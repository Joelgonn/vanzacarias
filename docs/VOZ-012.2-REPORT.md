## 3. Alterações Realizadas

### 3.1 Controller (`voiceController.ts`)

- **Novo estado `processing`**: `VoiceStatus` ganhou `'processing'`; campo `private processing` com transições corretas e cleanup em `cancel()`/`dispose()`/abort. Guard de concorrência do `start()` agora inclui `processing`.
- **Fluxo de stop()**: imediatamente após `recorder.stop()`/cleanup, emite `processing` → `setStatus('processing')` (antes de qualquer `await`/resample). Depois `processing=false` → `transcribing` → `result`. CSS do tempo de resample agora aparece como "Processando...", não mais "Gravando".
- **Limite de 60s** (`RECORDING_LIMIT_MS`): `setTimeout` armado **apenas quando `recording` de fato começa** (junto de `setStatus('recording')`). Ao disparar → `handleRecordingLimit`: informa o usuário (`code: 'limit_reached'`, mensagem "Limite de gravação de 60 segundos atingido. O áudio já capturado será convertido em texto.") e chama `void this.stop()` → **o áudio capturado é processado normalmente, sem descarte e sem duplicação** (o timer é limpo no início do stop; guard `if (!this.recording) return` torna o re-disparo inofensivo).
- **Timer limpo** em: `stop()` (imediatamente — cronômetro para ao PARAR), `cancel()`, `dispose()`, e no caminho de falha de load.

### 3.2 Hook (`useVoiceInput.ts`)

- **`formatElapsedMs(ms)`** exportado: `MM:SS`, valores inválidos → `00:00`.
- **`recordingElapsedMs`**: estado do cronômetro. `useEffect` ligado a `[status]`:
  - `status === 'recording'` → marca `Date.now()` de início e roda `setInterval(250ms)` atualizando `elapsed = Date.now() - início` (**tempo de parede**, não duração de áudio).
  - qualquer outro status → `clearInterval`, zera `recordingElapsedMs` (não conta durante `PROCESSANDO`/`TRANSCRIBENDO`; nova gravação começa em `00:00`).
- **`isBusy`** agora inclui `'processing'` (bloqueia FALAR e mostra spinner durante o processamento).

### 3.3 Chat (`ChatAssistant.tsx`)

- Import de `formatElapsedMs`.
- Status bar (mensagens curtas por estado):
  - `Gravando {formatElapsedMs(voice.recordingElapsedMs)} — toque no microfone para parar` (ponto pulsante rosa mantido).
  - `Processando...` (estado `processing`).
  - `Transcrevendo...` (estado `transcribing`).
  - `Preparando...` (estado `loading` — corrige o texto genérico anterior).
  - erro continua em rosa.
- Indicador visual do botão mantido: Square (parar) ao gravar, Loader2 (spinner) ao `isBusy`, Mic no idle.

## 4. Decisões de UX

- **PROCESSANDO explícito**: o resample de áudio longo acontece no main thread e pode levar dezenas de ms; statusbar deve refletir isso, senão o usuário vê "Gravando" parado após o PARAR.
- **Cronômetro = tempo de gravação real** (`Date.now()`), nunca derivado de `pcm.duration`. Começa junto do `recording`, para no `PARAR` e é zerado em qualquer saída de `recording`.
- **Limite via `onError` (code `limit_reached`)**: reutiliza o canal informativo existente (mesmo padrão de "Nenhuma fala detectada" que já é entregue como erro leve), sem criar mecanismo paralelo; mensagem é clara e não alarmista ("será convertido em texto"). Não é política de produto — apenas proteção de UX com preservação do áudio.
- **Sem animações novas**: nenhuma (apenas o ponto pulsante já existente). Sem segunda máquina de estados: reutiliza o `VoiceStatus` do controller.
