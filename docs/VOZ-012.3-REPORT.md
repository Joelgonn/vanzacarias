## 1. Estado Inicial

- **F02 confirmado em `src/lib/voice/stt/vosk.ts`:** `const guard = setTimeout(() => finish(), 30000)` — guard **fixo de 30s** para qualquer duração de áudio.
- **O guard cortava inferências válidas:** em dispositivo mid-range (RTF > 1 do WASM worker em Android), áudio longo pode ser legitimamente processado em >30s. Ao expirar, o guard chamava `finish()` e resolvia o texto **parcial/vazio** — como se a inferência tivesse terminado. ## 3. Alterações Realizadas

### 3.1 Guard proporcional (`vosk.ts`)

- **Constantes:** `INFERENCE_GUARD_BASE_MS = 30_000`, `INFERENCE_GUARD_FACTOR = 4`.
- **Helper puro exportado:** `computeInferenceGuardMs(audioDurationMs, baseMs = INFERENCE_GUARD_BASE_MS, factor = INFERENCE_GUARD_FACTOR)`:
  - Fórmula: `timeoutMs = base + factor × audioDurationMs`.
  - **Sanitização determinística:** durções inválidas/negativas/NaN/Infinity → `0` → só a margem base (30s). Nunca timeout negativo/zero/Infinity.
- **Uso:** `const timeoutMs = computeInferenceGuardMs(audioDurationMs)` e `const guard = setTimeout(() => finish(true), timeoutMs)` — o guard agora é rede de segurança que **rejeita com erro controlado**, nunca corta inferência válida.

### 3.2 Semântica do guard: erro controlado, não truncamento

- **`finish(isTimeout = false)`**:
  - Sem argumento (fluxo normal, disparado por contagem F01) → resolve o texto acumulado (comportamento preservado).
  - `finish(true)` (guard) → `VOSK_TIMEOUT` log + `cleanup()` + **`reject(Error('Vosk INFERENCE_TIMEOUT (guard …ms para …ms de áudio)'))`**. **Não** resolve texto parcial/truncado como inferência válida. O listener do `VoiceController` trata a rejeição como "erro controlado" e exibe a mensagem amigável vazia já existente.
- **`cleanup()` extraído** (usado por finish/error): `recognizer.remove()` com try/catch.

### 3.3 Instrumentação

- **`VOSK_RESULT`:** adicionados `audioDurationMs` e `timeoutMs`. **`acceptToRetrieveMs` redefinido** de `retrieveStart - acceptEnd` (≈0, inútil) para `resultReceivedAt - acceptEnd` — **tempo de retorno real do worker** (métrica que a auditoria pede).
- **`VOSK_RETRIEVE`:** adicionados `audioDurationMs` e `timeoutMs`.
- **`VOSK_TIMEOUT` (novo log, apenas em debug):** `samples/originalSamples/sampleRate/audioDurationMs/acceptStart/resultReceivedAt/inferenceMs/timeoutMs/segmentsReceived`.
- **Sem áudio/texto/PII novos** — apenas métricas e duração.

### 3.4 Máximo do guard (sem teto explícito, decidido)

- Sem teto arbitrário; a duração máxima é limitada pelos **60s de gravação** (VOZ-012.2): `timeoutMax ≈ 30s + 4×60s = 270s`. Não há cenário real que exceda; teto explícito só reintroduziria o risco de corte de inferência válida.

---

## 4. Decisões Técnicas

- **Fórmula `base + k×duração` (recomendação da auditoria externa):** a base de 30s absorve latência por-chunk, setup wasm/worker e a janela até o primeiro resultado — independente do tamanho do áudio. O termo proporcional acompanha o crescimento real do trabalho.
- **`k = 4`** (faixa recomendada 3–5): justificado porque o RTF típico do WASM worker em dispositivo mid-range é 1–3×; k=4 garante folga ~1–3× sobre o processamento esperado. `k<3` arriscava timeout falso em gravação longa; `k>5` alongava a espera em trava real. Não há custo funcional para o usuário porque o guard só decide quando o worker realmente não responde.
- **Timeout = rejeição com erro controlado** (não resolução com texto parcial): preserva a integridade do resultado — texto parcial nunca é apresentado como transcrição final; a UI reutiliza a mensagem amigável de erro vazio.
- **`acceptToRetrieveMs = resultReceivedAt - acceptEnd`:** mede o turnaround do worker (primeira resposta), que é a métrica diagnóstica relevante para F02 (RTF). `retrieveStart - acceptEnd` era zero por construção (chamadas síncronas consecutivas) e foi substituído.
- **Helper puro exportado:** permite teste determinístico do cálculo (T1/T2/T3/T6) sem tocar timers reais.
